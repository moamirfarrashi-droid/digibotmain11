# DigiBot — نسخه ساده ۲

این نسخه برای آپلود همه فایل‌ها در صفحه اصلی مخزن آماده شده است. فایل bot.py، فایل‌های JSON و تست همگی در ریشه هستند. **فقط publish.yml باید به مسیر مخصوص GitHub منتقل شود.**

## مرحله ۱ — آپلود

ZIP را Extract کنید و همه فایل‌های داخل آن را با Add file → Upload files در صفحه اصلی مخزن آپلود کنید. خود ZIP را آپلود نکنید. فایل‌های قبلی هم‌نام را با این نسخه جایگزین کنید.

پوشه data یا tests لازم نیست. اگر از نسخه قبلی پوشه‌هایی ساخته‌اید، این نسخه از آن‌ها استفاده نمی‌کند.

## مرحله ۲ — فعال‌کردن فایل زمان‌بندی

اگر فایل `.github/workflows/publish.yml` ندارید:

1. فایل publish.yml در صفحه اصلی مخزن را باز کنید.
2. مداد Edit را بزنید.
3. در قسمت نام فایل بالای ویرایشگر، نام را به `.github/workflows/publish.yml` تغییر دهید.
4. Commit changes را بزنید.

اگر این مسیر از قبل وجود دارد، فایل همان مسیر را Edit کنید و کل محتوایش را با محتوای publish.yml جدید جایگزین کنید. وجود publish.yml در صفحه اصلی به‌تنهایی زمان‌بندی را فعال نمی‌کند. فقط یک workflow انتشار فعال نگه دارید.

## مرحله ۳ — اتصال تلگرام

در @BotFather دستور /newbot بفرستید و بات جدید بسازید. همان بات را در کانال اصلی و یک کانال عمومی آزمایشی جدا مدیر کنید و مجوز Post Messages بدهید.

در Settings → Secrets and variables → Actions → Secrets، سه New repository secret بسازید:

| نام | مقدار |
|---|---|
| TELEGRAM_BOT_TOKEN | توکن بات جدید |
| TELEGRAM_CHANNEL_ID | @digihinet |
| TELEGRAM_TEST_CHANNEL_ID | @آیدی کانال آزمایشی |

توکن را در فایل‌ها قرار ندهید. کانال آزمایشی باید جدا باشد.

## مرحله ۴ — مجوز ذخیره سابقه

Settings → Actions → General → Workflow permissions → Read and write permissions → Save.

مخزن باید اجازه push بات به شاخه اصلی را بدهد؛ برای این نسخه PAT لازم نیست.

## مرحله ۵ — پیش‌نمایش و تست

Actions → DigiHinet Channel → Run workflow

ابتدا mode=preview و kind=card را بزنید. هیچ پیامی ارسال نمی‌شود. پس از پایان اجرا، فایل post-preview را در Artifacts دانلود کنید. متن و تصویر داخل آن است.

سپس mode=test و kind=card را انتخاب کنید؛ ارسال واقعی فقط در کانال آزمایشی انجام می‌شود. برای هر کانال، روزی یک ارسال مجاز است. برای بررسی چند نوع محتوا در همان روز از preview استفاده کنید.

## مرحله ۶ — روشن‌کردن انتشار اصلی

Settings → Secrets and variables → Actions → Variables → New repository variable

Name: ENABLE_POSTING

Value: true

انتشار روزانه فعال می‌شود. برای انتشار فوری، Run workflow → mode=publish → kind=auto را انتخاب کنید. **publish واقعاً به کانال اصلی پیام می‌فرستد.** برای توقف، ENABLE_POSTING را false کنید.

## محتوا و تقویم

این بسته ۲۴ متن آموزشی و ۸ کارت تصویری دارد. مقاله‌ها از ۳۰ نوشته تازه منتشرشده سایت خوانده می‌شوند؛ گزیده پاراگراف نمایش داده می‌شود و خلاصه‌نویسی AI انجام نمی‌شود. یک نمونه‌کار اولیه رونکا دارد و MP4 داخل صفحه پروژه در زمان اجرا شناسایی می‌شود. افزودن پروژه‌های دیگر دستی است.

هر روز حدود ۱۸:۱۷ تهران؛ زمان‌بندی GitHub تضمین دقیق ندارد.

- شنبه: متن آموزشی
- یکشنبه: مقاله با تصویر شاخص، در صورت وجود
- دوشنبه: ویدیوی نمونه‌کار، در صورت دسترسی
- سه‌شنبه: کارت تصویری
- چهارشنبه: متن آموزشی
- پنجشنبه: معرفی تصویری نمونه‌کار
- جمعه: متن آموزشی

اگر مقاله، ویدیو یا پروژه جدید نبود، آموزش متنی یا کارت منتشرنشده جایگزین می‌شود. محتوای استفاده‌شده تکرار نمی‌شود. اگر کل بانک تمام شود اجرا خطا می‌دهد تا محتوای جدید اضافه کنید. تولید نامحدود AI، خبر روز، تولید ویدیو و نظرسنجی در این نسخه وجود ندارد.

## تغییر ساعت

فایل `.github/workflows/publish.yml` را ویرایش کنید. مقدار پیش‌فرض cron برابر `47 14 * * *` به وقت UTC است. تهران ۳:۳۰ جلوتر است؛ برای ساعت ۱۰:۱۷ تهران از `47 6 * * *` استفاده کنید.

## افزودن محتوا

در posts.json یک رکورد با id یکتا اضافه کنید:

```json
{"id":"tip-025","type":"text","title":"عنوان","body":"آموزش کوتاه و کاربردی"}
```

برای کارت، type را card بگذارید و card_text کوتاه هم اضافه کنید. کپشن عکس باید کوتاه باشد و متن کارت در قاب جا شود. پیش‌نمایش بگیرید.

در portfolio.json، مشابه نمونه موجود رکورد جدید اضافه کنید. url صفحه پروژه و media آدرس تصویر پروژه است. اگر media خالی باشد کارت ساخته می‌شود. بات برای حالت video، فایل MP4 داخل تگ video یا source صفحه پروژه را می‌خواند. فقط اطلاعات واقعی پروژه را درج کنید.

کارت‌ها از رنگ‌های برند و امضای متنی DigiHinet استفاده می‌کنند؛ فایل لوگوی رسمی و فونت اختصاصی در بسته نیست.

## ارسال نامشخص و pending

پیش از ارسال، وضعیت pending در state.json روی GitHub ثبت می‌شود. پس از تأیید تلگرام، رکورد به sent منتقل می‌شود. اگر ارتباط قطع شود، بات تا تعیین وضعیت متوقف می‌ماند تا دوباره ارسال نکند.

1. کانال نوشته‌شده در pending را بررسی کنید.
2. اگر پست منتشر نشده، pending را null کنید و Commit بزنید.
3. اگر پست منتشر شده، رکورد pending را با همان id/channel/date/type به انتهای sent اضافه کنید، message_id واقعی را به آن بیفزایید و pending را null کنید.
4. فقط پس از تعیین تکلیف، دوباره اجرا کنید؛ کل سابقه sent را پاک نکنید.

شماره message_id در انتهای لینک پست است، مانند 123 در https://t.me/digihinet/123.

401 یعنی مشکل توکن؛ 403 معمولاً مجوز ارسال؛ 400 نیازمند بررسی شناسه کانال، متن یا رسانه است. خطای git push را با مجوز نوشتن و تنظیمات شاخه بررسی کنید. خطاها در Actions دیده می‌شوند؛ هشدار خصوصی جداگانه ندارد.

ویدیو باید MP4 عمومی و قابل دریافت برای تلگرام باشد؛ سقف فعلی sendVideo معمولی ۵۰ مگابایت است. این نسخه ویدیو را تبدیل یا فشرده نمی‌کند. اگر ارسال ویدیو رد شد، pending را تعیین تکلیف و با متن یا کارت ادامه دهید.

## هزینه و نگهداری

اجرای استاندارد Linux در مخزن عمومی GitHub طبق شرایط فعلی رایگان است؛ مخزن خصوصی سهمیه دارد. خود Bot API معمول تلگرام رایگان است. استفاده از رسانه سایت از ترافیک هاست فعلی مصرف می‌کند. فایل‌های مخزن عمومی قابل مشاهده‌اند؛ داده محرمانه وارد نکنید.

زمان‌بندی مخزن عمومی ممکن است پس از ۶۰ روز بی‌فعالیتی غیرفعال شود؛ وضعیت Actions را دوره‌ای بررسی کنید. برای مدیریت بات از Run workflow استفاده کنید؛ بات فرمان تعاملی تلگرام ندارد.

## اجرای محلی اختیاری

Python 3.12:

```bash
pip install -r requirements.txt
python -m unittest test_bot -v
python bot.py --mode preview --kind card
```

برای کارت در ویندوز، FONT_PATH را به مسیر یک فونت TTF فارسی، مانند C:\Windows\Fonts\tahoma.ttf تنظیم کنید. GitHub روی Linux فونت DejaVuSans دارد.
