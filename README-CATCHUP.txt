افزونه جبران ارسال‌های عقب‌افتاده دیجی‌هاینت

هدف: اگر اجرای یک نوبت GitHub انجام نشد، اجراهای بعدی آن پست آماده را پیدا و ارسال کنند.
این افزونه مشکل زمان‌بندی GitHub را حذف نمی‌کند؛ در اولین اجرای در دسترس، عقب‌ماندگی را جبران می‌کند.
انتشار رأس دقیقه و تضمین مطلق در قطعی تلگرام، GitHub یا نامعتبر بودن توکن ممکن نیست.

نصب روی ریپازیتوری moamirfarrashi-droid/digibotmain11:
۱. ZIP را Extract کنید. هر چهار فایل بدون پوشه هستند.
۲. هر چهار فایل را در ریشه ریپازیتوری آپلود و Commit کنید.
۳. فایل catchup.yml را در GitHub باز کنید و Edit بزنید. نام بالای ویرایشگر را به این مسیر تغییر دهید:
.github/workflows/catchup.yml
سپس Commit changes کنید.
۴. در Actions گزینه DigiHinet Catch Up نمایش داده می‌شود.
۵. یک‌بار Run workflow بزنید. این اجرای واقعی است و محتوای عقب‌افتاده کانال اصلی را منتشر می‌کند؛ پیش‌نمایش نیست.
۶. پس از نصب، بررسی خودکار هر پنج دقیقه برنامه‌ریزی شده است و به اجرای دستی مداوم نیاز ندارد. GitHub می‌تواند نوبت‌ها را دیر اجرا یا حذف کند؛ اجرای بعدی دوباره سابقه را بررسی می‌کند.

فایل‌های فعلی campaign20.py و ai_daily.py و news_fa.py و گزارش مدیران دست‌نخورده می‌مانند.
فایل‌های state و تاریخ شروع کمپین‌ها را پاک یا تغییر ندهید.
همان Secretهای TELEGRAM_BOT_TOKEN و TELEGRAM_CHANNEL_ID استفاده می‌شوند.
Variables زیر برای انتشار مربوطه باید true باشند:
ENABLE_POSTING
ENABLE_AI_POSTING
ENABLE_AI_NEWS

رفتار دقیق:
- محتوای آماده عادی و AI: تمام نوبت‌های موعدرسیده از تاریخ شروع بررسی می‌شوند، حتی اگر روز قبل جا مانده باشند.
- ترتیب جبران برای محتوای آماده براساس زمان برنامه اصلی است. در هر اجرای افزونه حداکثر چهار پست آماده برای ارسال تلاش می‌شود، با حدود ده ثانیه فاصله؛ باقی در اجراهای بعدی جبران می‌شود.
- اگر AI در کانال اصلی هنوز شروع نشده، در اولین بررسی بعد از موعد صبح، روز اول را از همان روز شروع می‌کند. شروع کمپین موجود تغییر نمی‌کند.
- اگر چند نوبت از دست رفته باشند، ممکن است در اجرای اول چند پست نزدیک به هم ارسال شوند.
- ارسال‌های تأییدشده با شناسه محتوا دوباره ارسال نمی‌شوند.
- قبل از ارسال، pending در Git ذخیره می‌شود؛ اگر ذخیره شکست بخورد، ارسال انجام نمی‌شود.
- در رد صریح Telegram، pending پاک می‌شود و اجرای بعدی می‌تواند دوباره تلاش کند.
- در پاسخ نامشخص شبکه، pending باقی می‌ماند؛ ارسال خودکار همان دسته متوقف می‌شود تا پیام تکراری ساخته نشود. ابتدا خود کانال را بررسی کنید؛ بدون بررسی pending را حذف نکنید.
- خطای یک دسته مانع بررسی دسته دیگر نیست؛ Workflow برای وجود خطا قرمز می‌شود تا مشخص باشد بررسی لازم است.
- خبر: فقط نوبت‌های امروز را جبران می‌کند تا خبر روزهای قبل با تاریخ اشتباه ارسال نشود. وجود خبر تازه و مناسب شرط ارسال است. در صورت نبود خبر، بررسی منابع حداکثر هر نیم‌ساعت تکرار می‌شود.
- برای خبر بدون منبع معتبر، خبر ساختگی یا خبر قدیمی ارسال نمی‌شود.
- تاریخ start_date و شناسه‌های قبلی حفظ می‌شوند؛ سابقه جدید با گزارش فعلی و داشبورد سازگار است.
- اجرای هم‌زمان با ورک‌فلوهای قبلی و گزارش‌گیری با گروه مشترک digihinet-publisher کنترل می‌شود.
- دو ورک‌فلوی قبلی را لازم نیست تغییر دهید. افزونه مکمل آن‌هاست، نه بات جدید.

این بسته شامل فقط publish_due.py و test_publish_due.py و catchup.yml و همین راهنماست.
تست‌ها آفلاین هستند؛ تست ارسال واقعی بعد از نصب با توکن موجود شما انجام می‌شود.
